Presentation Gamma - 10 slides
Sujet : LogiChain - API REST + Base de donnees MongoDB
Style souhaite : presentation professionnelle, claire, moderne, orientee projet informatique. Utiliser des schemas simples, des pictogrammes tech/logistique, et une mise en page sobre. Une slide = une idee principale. Eviter les longs paragraphes.

SLIDE 1 - LogiChain : API + Base de donnees
Titre principal :
LogiChain

Sous-titre :
API REST et base de donnees pour la logistique evenementielle

Contenu :
- Projet backend realise en Node.js, TypeScript, Express et MongoDB
- Objectif : centraliser, tracer et piloter les operations logistiques d'un evenement
- Documentation interactive avec Swagger

Visuel suggere :
Schema simple montrant un evenement, des agents terrain, une API et une base MongoDB.

Problemes a resoudre :

- Connaitre leur zone, leur statut et leur responsable

Carte d'evenement avec zones, equipements et alertes.

SLIDE 4 - Architecture technique
Titre :
Une architecture N-Tier structuree

Contenu :
Le code est separe en couches avec des responsabilites precises :

- Models : schemas MongoDB, validations, index, GeoJSON
- Repositories : acces exclusif a la base de donnees
- Services : logique metier et regles de gestion
- Controllers : adaptation des requetes HTTP
- Routes : exposition des endpoints REST

Benefices :
- Code plus lisible
- Maintenance plus simple
- Separation claire entre API, metier et base de donnees

Visuel suggere :
Diagramme en couches : Routes -> Controllers -> Services -> Repositories -> MongoDB.

SLIDE 7 - Securite et validation
Titre :
Une API protegee et controlee

Contenu :
Elements mis en place :
- Authentification par JWT
- Routes protegees par header Authorization: Bearer token
- Roles : admin, logistic_manager, field_agent, provider
- Autorisations differentes selon les actions
- Validation des entrees avec Zod
- Validation des schemas avec Mongoose
- Gestion standardisee des erreurs HTTP

Exemples de codes :
- 401 : token absent ou invalide
- 403 : role insuffisant
- 409 : conflit de synchronisation
- 422 : donnees invalides


SLIDE 8 - Tracabilite et offline-first
Titre :
Garder une trace fiable du terrain

Contenu :
Chaque equipement possede :
- Un statut
- Une zone
- Un responsable
- Un historique d'actions
- Une version offline

Principe offline-first :
- Le terrain peut enregistrer des operations localement
- Les operations sont envoyees ensuite a /api/v1/sync
- L'API compare expectedOfflineVersion avec la version en base
- Si les versions correspondent : operation appliquee
- Sinon : conflit 409 pour eviter d'ecraser des donnees recentes

Visuel suggere :
Flux Agent terrain -> Sync API -> Verification version -> MongoDB.
